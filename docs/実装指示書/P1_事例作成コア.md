## 1. この指示書の位置づけ

本書はP1「事例作成コア」をClaude Codeが実装するための実装指示である。

本書は正本を要約して置き換えるものではない。
正本と本書が矛盾する場合は正本を優先し、実装を止めて報告する。

P1では以下までを完成させる。

1. 営業担当者が分かる範囲で案件を作成・保存・再開できる
2. 資料を添付し、テキスト抽出・OCR結果をsourceとして扱える
3. AIが案件全体を理解し、candidate factを作る
4. AIが販売事例として本当に不足している情報だけを原則1回の質問バッチで提示する
5. 利用者が回答・不明・後で確認・省略を保存できる
6. 利用者がcandidate factを根拠とともに確認・修正・却下・要確認できる
7. confirmed factまで作成できる
8. 中断・再開、version競合、履歴、根拠追跡が成立する

P1では編纂、公開、検索、コメント、A4/PDF、管理画面の完成は行わない。

## 8. 資料添付

対応形式:

- PDF
- JPG / JPEG
- PNG
- DOCX
- XLSX
- PPTX
- TXT
- CSV

上限:

- 1ファイル最大20MB
- 1案件あたり有効添付最大10ファイル
- 合計最大200MB

保存:

- binaryはGoogle Cloud Storage
- DBにはmetadataとstorage key
- storage keyを通常クライアントDTOへ返さない
- upload/downloadは認可済みの期限付きURL等を使用

抽出:

- テキストPDF: 直接抽出
- 画像PDF / JPG / JPEG / PNG: Document AI Enterprise Document OCR
- DOCX: parser
- XLSX: parser
- PPTX: parser
- TXT / CSV: 直接読込

判読不能・低確度:

- 読めたことにしない
- 推測で補わない
- extraction warningを保持
- UIで要確認表示
- AIへ確定sourceと同じ確度で渡さない

削除:

- logical delete
- confirmed fact参照中なら `ATTACHMENT_IN_USE`
- extraction失敗は再抽出可能

## 12. 2回目質問

通常フローでは自動生成しない。

許可条件は次だけ。

1. 1回目回答によって重大な矛盾が新たに生じた
2. 1回目回答によって新しい重要論点が判明し、それがないと事例因果が成立しない
3. 利用者が明示的に追加取材を実行した

単に未入力domainが残っているだけでは生成しない。

fixed fallback質問連鎖を実装しない。

## 13. 回答状態

各質問は:

- answered
- unknown
- later
- skipped

を保存できること。

ルール:

- 空欄とunknownを区別
- laterは保留
- fact review後もlaterへ戻って回答可能
- 後日回答をsource化し、関連candidateを再評価
- unknown / skipped / 会話制御返答は事実化しない
- 回答送信後に次質問を自動生成しない

## 15. factルール

confirmed条件:

- 根拠sourceあり
- case一致
- 利用者確認済み
- AI推論だけではない

修正:

- 元candidateを消さない
- 新factを作成
- 旧factをsuperseded
- 履歴追跡可能

手動追加:

- manual sourceを作成
- 追加直後はcandidate
- confirm操作を経てconfirmed

duplicate:

- 完全一致
- 数値・固有名詞を除いた意味近似
- 同domain意味重複
- 既存confirmedとの重複

conflict:

- 数値
- 日付
- 固有名詞
- 結果
- その他明確な矛盾

AIだけで統合・破棄しない。

## 26. 停止条件

次の場合は独断で進めず停止する。

- 正本同士に矛盾を発見
- 本書と正本が矛盾
- Google Cloud / OpenAIの必要権限がない
- 仕様確定を要する新論点
- 既存の他AI変更と競合
- データ損失リスク
- 正本を変更しなければ実装できない

停止時は、事実、該当ファイル、該当箇所、影響、推奨対応を報告する。
