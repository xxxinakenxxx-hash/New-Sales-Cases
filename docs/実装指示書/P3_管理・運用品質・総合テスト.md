## 7. server-side authorization

すべての管理APIで共通middleware/serviceを使用する。

判定順:

1. authenticated
2. active user
3. DB上role
4. action permission
5. target ownership/status

クライアント送信role/branchを権限根拠にしない。

ID直指定でも同じ認可を通す。

## 8. input validation / XSS

Zodで全API入力をvalidate。

表示:

- Reactの通常escapeを維持
- `dangerouslySetInnerHTML` を業務本文・comment・memoに使用しない
- Markdownを導入する場合はsanitize済みrendererのみ

comment / memo / customer name / compilation expression edit / master nameをXSS fixtureでテストする。

## 9. signed URL

attachment / PDF downloadのsigned URLは短寿命。

MVP固定:

- upload: 15分
- download: 5分

URL発行前に毎回authorizationを再確認する。

## 10. security headers

Cloud Run / Next.jsで最低限:

- Content-Security-Policy
- X-Content-Type-Options: nosniff
- Referrer-Policy
- frame-ancestors制御
- Strict-Transport-Security（HTTPS環境）

を設定する。

### 途中離脱

初期値14日。

対象:

- archivedではない
- suspendedではない
- active publicationなし
- 最終進行イベントから14日以上

進行イベント発生で対象外へ戻る。

集計時に派生判定し、caseへ離脱フラグを恒久保存しない。

## 14. error handling

業務エラーは正本error codeへ統一。

Cloud Loggingへ:

- requestId
- error code
- route
- actor user id
- case id
- stack
- timestamp

を送る。

送らない:

- access token
- API key
- OpenAI request/response全文
- source全文
- attachment本文
- comment全文

UIには:

- 何が失敗
- 何が保存済み
- 次の操作

を表示する。

## 15. recovery

### AI失敗

- source保持
- case状態を壊さない
- retry可能
- 二重candidate作成防止

### attachment失敗

- 他attachment/sourceを壊さない
- failed状態保持
- retry可能

### publication失敗

transaction rollback。
active publicationとsearch indexを必ず整合。

### PDF失敗

publication/compilationに影響させない。
失敗exportはactive扱いしない。

### 二重送信

P1のidempotency機構を全更新系へ適用。
