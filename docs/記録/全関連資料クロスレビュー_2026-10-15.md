## 2. 最優先方針の照合結果

### 2.1 アプリ目的

全正本で、中心目的を「営業担当者の断片的な案件情報を、AIで他の営業が再利用できる販売事例へ仕上げ、社内で蓄積・検索・再利用する」に統一した。

旧資料の「カード型事例DB」「利用分析中心」だけを目的にはしない。

### 2.2 greenfield方針

現行正本・README・CLAUDE・運用ルールを以下へ統一した。

- 旧コード・旧DB・旧API・旧画面・旧テストは新アプリの実装基盤として再利用しない
- 旧プロジェクトから引き継ぐのは、設計段階で文章化して正本へ反映した知見・失敗知見だけ
- 旧コードを調査して再利用可否を決める工程は設けない
- 新正本から新規実装する

### 2.3 技術選定の時点

技術選定をP0や実装工程へ先送りしない。

`docs/正本/技術選定理由書.md` を設計正本として追加し、基本アーキテクチャを設計段階で固定した。

開発工程表からP0は削除済み。

### 2.4 公開範囲

公開済み販売事例は、認証済み社内利用者が全社横断で検索・閲覧できる。

拠点・部門・manager管轄を閲覧制限に使わない。

manager専用の「管轄案件閲覧」はMVPに設けない。

### 2.5 コメント

コメントはMVP必須。

- 公開済み販売事例が対象
- 認証済み社内利用者が投稿
- 自分のコメントは編集・削除可能
- admin / sysadminは管理削除可能
- confirmed factではない
- AI案件理解・編纂へ自動投入しない
- case単位で保持し、投稿時publication版を記録
- 改訂・再公開でも保持
- 公開停止中は通常表示・新規投稿を停止
- 検索索引へ含めない
- A4/PDFへ含めない

## 4. 今回検出・修正した不整合

### CR-01 要件定義書に旧コード再利用判定が残存

問題:
要件定義書§23に「旧コードを再利用 / 改修 / 廃止 / 新規へ分類」が残っていた。

修正:
greenfield方針へ統一し、旧コード等を実装基盤として再利用しないと明記した。

### CR-02 「なぜやり直すのか」に旧GAS資産再利用が残存

問題:
旧GAS・スプレッドシート等を再利用候補とする記載が残っていた。

修正:
残すものを設計知見・失敗知見だけに変更し、新規実装順へ改訂した。

### CR-03 開発運用ルールに旧実装分類が残存

問題:
旧コードを再利用・改修・廃止へ分類する運用が残っていた。

修正:
旧実装は再利用せず、新規実装後は新リポジトリ内の現行実装だけを調査対象とする形へ変更した。

### CR-04 README / CLAUDE / TASK_CURRENTが現在地不足

修正:
- READMEの最初に読む資料と現在地を更新
- CLAUDEへ技術選定理由書・設計知見整理を追加
- Claudeへ旧アプリ資産を再利用しないことを明記
- TASK_CURRENTを実装前設計確定段階へ更新

### CR-05 統合設計の認証が「未確定」のまま

修正:
Google Workspaceアカウント + Google OpenID Connect + アプリ側user/role管理へ統一した。

### CR-06 添付保存・PDF方式が「技術選定後」のまま

修正:
- 添付: Google Cloud Storage + DB metadata/storage key
- PDF: 印刷専用HTML/CSS ViewModel + headless Chromium
へ統一した。

### CR-07 日本語全文検索方式が曖昧

問題:
単に「PostgreSQL全文検索」としており、日本語トークナイズの具体方針が弱かった。

修正:
PostgreSQL内の日本語全文検索を採用し、`pg_bigm` をMVP第一選択とした。採用するPostgreSQL major versionが正式サポート対象であることと、代表データでの検索品質を実装前に確認する。

### CR-08 技術選定理由が一覧化されていない

修正:
技術選定理由書に、Web基盤、実行基盤、DB、ファイル、認証、検索、PDF、AI adapterについて「採用 / 主な代替 / 理由」の比較表を追加した。

### CR-09 コメントの検索・PDF混入が未定義

問題:
コメントは非factと定義されていたが、検索索引・A4/PDFからの除外が明文化されていなかった。

修正:
コメントを検索索引・A4/PDFに含めないと要件・統合設計・APIへ明記した。

### CR-10 顧客名・金額の将来非表示時の漏えい境界が弱い

修正:
MVPは `internal / showCustomerName=true / showAmounts=true` 固定とし、一般利用者向け表示切替UIを作らない。将来falseを使う場合はカード、詳細、検索索引、印刷/PDFの全経路でサーバー側適用することを明記した。

### CR-11 branchが認可条件へ戻る余地

問題:
`validateCaseAccess_` の一般説明にbranchが含まれ、公開事例の全社閲覧方針と誤読可能だった。

修正:
公開済み事例の検索・閲覧ではbranchを認可条件に使わないとAPI一覧へ明記した。

### CR-12 AttachmentDTOが内部storageReferenceを露出

問題:
client DTOに内部storageReferenceが残っていた。

修正:
- client DTOからstorageReferenceを削除
- `downloadAvailable`へ変更
- `getAttachmentDownloadUrl` と短時間URL用DTOを追加
- 内部storage keyをclientへ返さない

### CR-13 API DTO定義欠落

API一覧を機械照合したところ、参照されるDTOの一部に定義がなかった。

不足していた主なDTO:
- CreateCaseInputDTO
- CaseSaveResultDTO
- CaseDetailForEditDTO
- ResumeStateDTO
- CaseListDTO
- AttachmentUploadDTO
- CaseUnderstandingResultDTO
- MissingInformationDTO
- QuestionBatchDraftDTO
- InterviewSubmitResultDTO
- PdfResultDTO
- FunnelDTO

修正後、参照DTOとDTO定義を再照合し、未定義DTOは0件になった。

### CR-14 更新系APIの二重実行防止が共通原則に不足

修正:
case作成、AI実行、upload完了、公開、コメント投稿、PDF生成等はrequestId / idempotency keyにより同一要求の二重実行を防ぐ原則をAPI一覧へ追加した。

### CR-15 添付再抽出APIにversion競合条件が不足

修正:
`retryAttachmentExtraction(caseId, attachmentId, expectedVersion)` とした。

### CR-16 OCR「判読不確実」の扱いが不足

問題:
完全な読取失敗は定義済みだったが、手書き・画像等で一部だけ判読不確実な場合の扱いが弱かった。

修正:
- 判読不確実と完全失敗を区別
- extractionWarnings / requiresReviewを保持
- 不確実範囲を確定原文として扱わない
- P1テストへ要確認表示を追加

### CR-17 過去クロスレビュー記録が現行仕様と混同可能

修正:
2026-10-14の2本のレビュー記録へ「履歴資料」であることを明記し、現在仕様は現行正本と最新CHAT_CURRENTを参照するよう注記した。

### CR-18 CHAT_CURRENTに撤回済み判断が現行のように残存

修正:
- listManagedCasesは当時追加後、現在は撤回済みと明記
- コメント将来候補は後続でMVP必須へ変更済みと明記
- P0は廃止済み
- 現在地と次工程を更新
