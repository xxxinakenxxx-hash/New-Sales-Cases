## 3. S-10 管理

admin:

- 利用者 active / inactive
- role
- 所属・拠点
- 業務マスター
- 公開状態管理
- コメント管理削除
- audit / activity / error log閲覧
- 全案件状態確認
- アーカイブ・復元

sysadmin:

- admin全権限
- system setting
- 障害調査・復旧
- 技術設定
- 外部連携設定

業務マスター:

- 顧客業種・業態
- 機械分類
- メーカー

自由編集不可:

- fact domain
- 状態値
- 権限種別
- 質問制御
- 編纂section
- 公開状態値

admin / sysadminもconfirmed-only編纂を迂回しない。
fact本文・編纂本文を管理画面から直接変更しない。
秘密値を表示しない。

## 4. 認証・認可

- Google Workspace OIDC
- active userのみ利用
- role / ownership / actionをサーバー側検証
- クライアント送信roleを信用しない
- 他人のdraftを通常利用者が取得・更新できない
- 公開済み事例は社内認証済み利用者が全社横断で閲覧可能
- manager固有の管轄閲覧制御は作らない

## 5. セキュリティ

必須:

- server-side authorization
- input validation
- ID書換え耐性
- XSS対策
- comment安全表示
- attachment access control
- signed URL短寿命化
- secret非露出
- ログ機密情報マスキング
- stack / token / API key / AI応答全文を通常画面・通常ログに出さない

## 6. ログ・監査

業務ログと技術ログを分離する。

業務ログはPostgreSQL。
技術ログはCloud Logging。

重要操作は「誰が・いつ・何を」を追跡可能にする。

source全文、AI応答全文、秘密値を不要にログ保存しない。

## 7. Analytics

最低集計:

- 作成開始
- AI理解実行
- 質問発生率
- 質問0件率
- 回答完了率
- fact確認完了率
- 編纂完了率
- 公開率
- 途中離脱
- 再開
- 検索回数
- 0件検索
- 事例閲覧
- コメント投稿 / 編集 / 削除

ランキングは作らない。

途中離脱:

- 最終進行イベントから14日以上
- archived除外
- suspended除外
- 有効publicationあり除外
- system settingで保持
- MVPではsysadminだけ変更可

## 8. Error / Recovery

対象:

- AI失敗
- 保存失敗
- 添付読取失敗
- 権限拒否
- version競合
- 公開失敗
- PDF失敗
- 二重送信

要件:

- 入力済みデータを失わない
- 再試行可能
- 二重データを作らない
- 中途半端なpublished状態を作らない
- 利用者に「何が失敗・何が保存済み・次に何をするか」を示す

## 11. MVP総合テスト

正本の総合シナリオA〜Hを実施する。

A 標準案件:
新規作成 → 入力 → 資料添付 → AI理解 → 質問 → 回答 → fact確認 → 編纂 → 確認 → 公開 → 検索 → 詳細 → コメント → A4/PDF

B 質問0件

C unknown / later / skippedあり

D 資料読取失敗

E 公開済み事例改訂

F 公開停止・再公開

G 複数端末version競合

H ID直指定 / role改変 / XSS等のセキュリティ

手作業DB修正や管理者介入を標準フローで必要としないこと。

## 12. AI販売事例品質テスト

最低5案件。

種類を偏らせない。

最低評価者:

- 案件を知る営業担当者
- 案件を知らない別営業担当者
- ChatGPTによる正本照合

評価:

- 事実正確
- AI創作なし
- 再質問不要
- 質問具体性
- 営業判断・工夫
- 壁と突破
- 成果
- 顧客の言葉
- 温度感
- 横展開性
- 因果
- 入力負担

重大不合格:

- 架空数値
- 架空顧客発言
- 根拠なし感情
- 既知情報再質問
- 逐次質問長期化
- fallback連鎖
- 会話制御返答fact化
- candidate大量重複
- 未confirmed本文混入
- 本人が「自分の案件と違う」
- 別営業が再利用方法を理解できない
