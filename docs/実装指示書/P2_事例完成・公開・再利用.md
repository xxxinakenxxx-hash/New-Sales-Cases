## 6. 編纂処理

編纂入力はconfirmed factだけ。

処理順:

1. caseのconfirmed facts取得
2. compilation readiness評価
3. sectionごとのfact候補整理
4. OpenAI APIへ編纂要求
5. JSON Schema検証
6. used fact refs検証
7. 創作検査
8. compilation draft保存
9. S-05へ表示

編纂section:

- title
- customer_background
- problem
- proposal
- selection_reason
- alternatives
- barrier
- breakthrough
- salesperson_judgment
- collaboration
- before_after
- result
- customer_quote
- salesperson_joy
- success_factor
- caution
- target_customer
- reuse_point
- story

各sectionは使用fact_idを必ず返す。

### 創作検査

最低限:

- usedFactIdsがすべてconfirmed
- 数値が使用factに存在
- 固有名詞が使用factに存在
- customer_quoteが原根拠に存在
- 感情表現がfactに存在
- proposalとselection_reasonの混同なし
- section本文が参照factの意味を逸脱していない

重大違反は保存前に `COMPILATION_SOURCE_INVALID`。

### 表現修正

表現修正は既存confirmed factの意味を変えない範囲だけ許可する。

保存前に `detectNewFactsInExpressionEdit_` を実行する。
新数値、新固有名詞、新顧客発言、新成果、新因果が追加された場合は保存拒否し、fact reviewへ戻す。

### version

- 再編纂は新version
- 表現修正も新version
- 旧versionは保持
- 公開済みversionは物理削除しない

## 8. 公開

公開条件:

- compilation.status = completed
- used fact refsがすべてconfirmed
- case操作権限あり
- active publicationとの競合なし

公開処理は単一transactionで:

1. publication新規/更新
2. search_index生成
3. case状態更新
4. activity log
5. 旧active publication停止

を整合させる。

外部処理を含めない。
「publishedだがsearch_indexなし」を作らない。

### 公開停止

単一transactionで:

- active publication = false
- search_index削除
- publication version更新
- activity log
- case状態は正本ルールに従う

comment、fact、compilationは削除しない。

### 改訂

- `startCaseRevision` でcaseをfact_reviewへ
- active publicationは維持
- 新fact / compilationを作成
- 再公開transaction時にactive publicationを新版へ切替
- commentはcase単位で維持

## 12. コメント

### API権限

- 一覧: 認証済み社内利用者 + active publication
- 投稿: 認証済み社内利用者 + active publication
- 編集/削除: 投稿者本人
- 管理削除: admin / sysadmin

### validation

- trim後空文字禁止
- 最大5000文字
- HTMLを信頼しない
- DBにはプレーンテキスト
- 表示時escape
- version競合必須

コメント投稿・更新・削除はactivity logを残す。

コメントはAI理解、fact、compilation、search_index、PDFへ自動投入しない。
